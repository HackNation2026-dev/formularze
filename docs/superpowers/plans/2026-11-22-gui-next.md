# Aplikacja GUI (Next.js) — plan wdrożenia

> **Dla workerów:** czytaj najpierw `docs/superpowers/specs/2026-11-22-gui-next-design.md`, `docs/08-implementacja/GUI-MAKIETY.md`, `docs/07-decyzje/ADR-002-gui-nextjs.md`, `design/tokens.css`. Kroki oznaczone `- [ ]`. Commituj małymi commitami po polsku (`feat(web): ...`), nie pushuj (pushuje koordynator), nie zmieniaj plików poza swoim zakresem.

**Cel:** pełna aplikacja `apps/web/` (Next.js, React, TypeScript, TanStack) z atomic design system, wszystkimi widokami i pełnym userflow na mock API.

**Spec:** `docs/superpowers/specs/2026-11-22-gui-next-design.md`

## Ograniczenia globalne
- Tylko `apps/web/`, `docs/`, `.github/workflows/web.yml`, `scripts/` (nowe). Nie zmieniaj `src/formgen/`, `tests/` (Python), `src/formgen/static/review/`.
- Zależności `npm install --save-exact`, lockfile w repo, bez CDN i zewnętrznych żądań w runtime; czcionki z `@fontsource*`.
- Licencje bez copyleftu (MIT, Apache-2.0, ISC, BSD, MPL tylko jako zależność dynamiczna po zgłoszeniu w raporcie).
- TypeScript strict, brak `any` bez komentarza, brak surowych kolorów (tylko tokeny), teksty w `messages/{pl,en}/*.json` z tymi samymi kluczami.
- Każdy komponent: typowane propsy, stany, test Vitest, wpis w katalogu `/[locale]/design-system`.
- Polecenia (w `apps/web`): `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`, `npm run e2e`; muszą przechodzić przed końcem zadania.
- Raport końcowy workera: lista commitów, wynik każdego polecenia, odstępstwa od planu, pytania.
